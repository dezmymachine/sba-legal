# AGENTS.md

## State
- Astro 7 + Tailwind v4 scaffold (verified 2026-09-15 via `npm run build`): `src/pages/index.astro` is homepage; stubs for about/expertise/people/knowledge/join-us/contact exist so nav never 404s.
- Knowledge posts come from Sanity (project `3dt82du8`, dataset `production`, public). Studio lives in `studio/` (own package.json) and is deployed at https://sba-website.sanity.studio. `src/lib/sanity.ts`: with `PUBLIC_SANITY_PROJECT_ID` set, Sanity is the only source (empty stays empty; fetch errors fail the build); unset, it uses the sample `ARTICLES` mocks. See `.env.example`.
- Post rendering: `ArticleBody.astro` uses `astro-portabletext` with site components in `src/components/portable-text/` (Block: h1/h2→h2, h3–h6→h3; Mark: vetted links; Image; Table from `@sanity/table`, first row = header). Sanity image fields stay raw in GROQ and go through `urlFor()` (`@sanity/image-url`) in `src/lib/sanity.ts` so studio crop/hotspot apply. Not used on purpose: `@sanity/astro` (embedded studio / visual editing need React + SSR; site is static with a separate studio).
- Packages: local `node_modules` is pnpm-managed; keep `package-lock.json` in sync with `npm install --package-lock-only` after `pnpm add`. Type-check `.ts` with `studio/node_modules/.bin/tsc --noEmit -p .` (`astro check` prompts to install `@astrojs/check`).
- People are code-managed (`PEOPLE` in `src/data/content.ts`). Sanity `person` docs exist only as article authors; slugs must match. After team changes run `cd studio && npx sanity exec scripts/seed-people.ts --with-user-token`.
- Static site: a published post appears only after a rebuild. Hosting is planned on Cloudflare Pages, with a Sanity webhook → Pages deploy hook.
- Nav: `NAV_ITEMS` in `src/data/content.ts`; items with `children` render as dropdowns (About Us → About the Firm, Our People, Join Us). Footer flattens them.
- Join Us form posts to FormSubmit (`https://formsubmit.co/chambers@sbalegalconsult.com`, multipart with CV attachment). First live submission sends an activation email to chambers@ that must be confirmed once. Site email is `SITE.email`.
- SEO (audit 2026-11-06, claude-seo method): indexing is opt-in. `src/lib/seo.ts` marks a Cloudflare build indexable only on `master` with `PUBLIC_SITE_URL` set; otherwise every page gets `noindex` and `robots.txt` (generated by `src/pages/robots.txt.ts`) serves `Disallow: /`. Set `PUBLIC_SITE_URL=https://sbalegalconsult.com` in Cloudflare only once the domain is live.
- Structured data: `src/lib/schema.ts` builders. BaseLayout always emits the firm (`LegalService`, `@id` `/#firm`) and merges each page's `jsonLd` prop (Person on bios, Article on posts, Service on `/expertise/<slug>`, BreadcrumbList, WebSite on home) into one `@graph`. `src/pages/llms.txt.ts` generates `/llms.txt` from the same data.
- Service pages: `src/pages/expertise/[slug].astro` from `SERVICES`; no people/advisers are shown on them (deliberate: org structure unconfirmed). Longer approved copy goes in a service's `body`.
- Long-form text (design rule, from The Verge): any multi-paragraph copy (bios, practice pages, about, articles) uses `.prose-sba` (`src/styles/global.css`; articles via `ArticleBody.astro`). 65ch measure, 17–19px type, 1.75 line-height, 1.5em paragraph gap, left-aligned, underlined links, ≥20px mobile side gutters (`px-5`). Mark a lead paragraph with `.prose-lead`. Never hand-set paragraph size/spacing or use `t-body` for stacked paragraphs.
- Images are WebP in `public/` (backgrounds ≤1920w, portraits 900×1200, homepage photos self-hosted in `public/images/`); keep each under 200KB and give every `<img>` width/height.
- Only content is `inspo/` (hand sketches + reference screenshots) plus scaffold. No test/lint/CI, no domain yet; staging first.
